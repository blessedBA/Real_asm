hrc scripts of colorer library

preface

HRC is a script language for parsing target text files for syntax highlighting. It based on xml language, so you can find DTD and XSL files in colorer distribution. At first, hrc is based on colorer regular expressions. So, you may wish to read cregexp.html documentation also.

hrc format

There are many hrc files in colorer distribution, but all of them looks like 

<?xml version="1.0" encoding="Windows-1251"?>
<!DOCTYPE hrc SYSTEM "hrc.dtd">
<?xml-stylesheet type="text/xsl" href="hrc.xsl"?>
<!--
     creator comments
-->
<hrc version="4ever">

<!-- base content -->

</hrc>

First three lines are standard xml includes, but block <hrc> defines all base colorer definitions. note, that version parameter is optional - it exist only in base colorer.hrc file.

colorer.hrc

This file contains definitions of all types and schemes includes. All base schemes definitions are included here also. This is part of this file: 

  <include name="regions.hrc"/>
  <include name="defines.hrc"/>

  <type descr="c++" name="cpp" exts="/\.(cpp)|(cxx)|(cc)|(hpp)|h$/i">
    <load name="base/cpp.hrc"/>
    <scheme name="cpp"/>
  </type>

Here you see <include name="filename.hrc"/> This tag tells colorer to include file "filename.hrc".

Next, <type ../> tag creates separate file type In our case this is a C++ language. exts parameter sets regular expression to match needed file names. Name and desctioption are used to describe symbolic name of each type.

Inside of each type tag we has <load name="base/cpp.hrc"/> It tells colorer where to search C++ language scheme. And, tag <scheme name="cpp"/> sets scheme name to assign with C++ file type.

Also you can use switch tag in type block: 

  <type descr="default" name="default" exts="//">
    <switch type="messages" match="/^from/i"/>
    <switch type="diff"     match="/^(diff)|(---)/i"/>
  </type>

It tells colorer to use regular expression and switch into new type, if it matches with first file line. We need this, because there are many types without extension, or multiple types with one extension.

base hrc content

Tag 

<define name="dNumber"    value="10"/>
defines region with name dNumber and with value 10. Syntax region defines one lexem it text. Also you can use it as 
<define name="dNumHex"    value="dNumber"/>
Here new dNumHex region is defined as dNumber region.

So, the main block in any hrc file is <scheme> block. It defines language scheme. Scheme can contain different parameters, let's start with

keywords

this block defines a set of keywords: 

  <keywords region="dKeyWord" ignorecase="ignorecase" worddiv="/[^\w_]/">
     <word name="asm"/>
     <word name="auto"/>
     <word name="break"/>
     <word name="case"/>
     <word name="cdecl"/>
     <word name="char"/>
     <word name="const"/>
     <symb name="->"/>
  </keywords>

you can define as words as symbols. Also you can ingore symbol's case (ignorecase parameter), and redefine word dividers symbol class using regexp class syntax.

regexp

This tag is used to define base regular expression for highlighting. It can parse any syntax constructions in one line: 

   <regexp match='/".*?"/' region0="dString"/>
   <regexp match="/'.*$/"  region0="dComment"/>
   <regexp match="/\b[0-9.]+(e|E[\-+]?\d+)?\B/" region0="dNumber"/>

regexp tries to find match in target text and highlight it with rules set (regionX).

block

this tag lets you to parse multiline constructions. 

   <block start="/\/\*/" end="/\*\//" scheme="Comment"
          region="cComment" region00="dpOpenStruct" region10="dpCloseStruct"/>

Two parameters - start and end are used to set regexps for start and end of block. Third parameter - scheme sets scheme to switch into. region0i and region1j are used to set each bracket's syntax region. region is used to set color of all block.

inherit

This tag lets you to make hrc-coding more easie. It lets you to inherit one theme from other. It means, your scheme will inherit all keywords, regexps, blocks and other inheritance from pointed scheme. 

<scheme name="Comment">
   <inherit scheme="mNetEMail"/>
   <inherit scheme="mNetURL"/>
</scheme>

Here you see definition of Comment scheme. We want to colorize in any comment scheme web and email addresses. So, we inherit appropriate schemes and everything will work. Note, that you can inherit big schemes - for example, you can inherit scheme "Cpp" from "C" and insert some new keywords - it is more easie then direct scheme coping.

notes about schemes

There are some rules of using blocks and inheritance. You can call block of not yet defined scheme - so, you can make forward references. But you can't inherit undefined scheme. inherit tag works only with already defined schemes.

virtual schemes

You can use scheme virtualization mechanizm. This is very powerful feature, that lets you to inherit schemes and redefine it's properties "inside". Look here: 

   <inherit scheme="c">
     <virtual scheme="c" subst="cpp"/>
   </inherit>

Here we inherits "C" scheme in "Cpp", but use extended "virtual" tag. this tag tells colorer to substitute needed scheme into new "subst" scheme. With this feature you can change work of any scheme as you wish.

full structure

So, look at end full hrc syntax: 

<?xml version="1.0" encoding="Windows-1251"?>
<!DOCTYPE hrc SYSTEM "hrc.dtd">
<?xml-stylesheet type="text/xsl" href="hrc.xsl"?>
<hrc ver="4ever">
  <define name="rname" value="regid"/>
  <include name="fname"/>
  <scheme name="sname">
    <inherit scheme="sname">
      <virtual scheme="sname" subst="sname"/>
    </inherit>
    <regexp match="//" regioni="rname" lowpriority="lowpriority"/>
    <block  start="//" end="//" scheme="sname"
            region="rname" regionij="rname" lowpriority="lowpriority"/>
    <keywords ignorecase="ignorecase" worddiv="/[]/" region="rname">
      <word name="wname" region="rname"/>
      <symb name="wname"/>
    </keywords>
  </scheme>
  <type descr="descr" name="tname" exts="//">
    <load name="fname">
    <scheme name="sname">
    <switch type="tname" match="//">
  </type>
</hrc>
