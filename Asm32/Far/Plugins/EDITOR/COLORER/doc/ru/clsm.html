небольшой мануал по библиотеке колорер

введение

В этом документе я попытаюсь дать небольшое описание того, как использовать колорер в виде библиотеки во внешних приложения на уровне кодинга - так что если вы не собираетесь использовать колорер как синтаксический парсер в своем проекте, вам и читать это незачем. Но всетаки...

Библиотеку вы можете использовать в двух вариантах - прямо компилировать в ваш проект (если он на языке C++) или же использовать отдельно скомпилированную DLL. Оба метода равноправны и совершенно одинаковы с точки зрения интерфейсов - второй лишь вызывает первый.

классы колорера

Существует два основных класса: CColorData и CColorer. Первый, CColorData, используется для компиляции и поддержки HRC-базы. Поэтому для начала вам надо вызвать 


  PColorData cd = new CColorData("libpath\\hrc\\colorer.hrc", "path\\to\\logfile");
  if (!cd->isok()){
    // fatal load error...
  };

Первый параметр - путь к основному файлу базы, второй (может быть NULL) - путь к файлу с логами компиляции. Этот вызов создаст базовый класс, в котором предварительно скомпилирует первичные определения из файла colorer.hrc. Заметьте, что вся база при этом вызове не компилируется. Так же нет необходимости создавать несколько экземпляров этого класса - одним классом может пользоваться одновременно хоть сколько парсеров.

Далее вам надо создать собственно сам парсер - CColorer. 

  PColorer cc = new CColorer();

Лучше, (на самом деле необходимо) чтобы для каждого разбираемого файла существовал свой экземпляр этого класса (это конечно справедливо, если ваш редактор поддерживает одновременное редактирование нескольких файлов). После создания этого объекта надо передать ему некоторую информацию. 

  // выбирает тип из hrc-базы
  type = cd->seltype(fname, GetLine(0, 0, 0, 0), 0);
  // загружаем выбранный тип - компилируем его схемы
  cd->loadtype(type);
  // Этот вызов дает парсеру информацию
  // о методах для запроса и возвращения информации
  // о парсинге, и сгенерированных синтаксических регионах...
  cc->SetServices(GetLine, 0, clrAddRegion, 0, 0, hlines);
  // Связывает парсер с конкретным типом
  cc->SetColoringSrc(type);

Процесс парсинга

Теперь после подготовки колорер готов к анализу текста. надо сказать пару слов о поддержке цветовых регионов. Вы должны предоставить парсеру методы для заполнения структур регионов. Здесь это был метод clrAddRegion. clr* - это набор функций по созданию, обработке, и подготовке к визуальному отображению синтаксических регионов. Эти функции связаны с другим классом - CAssign. Это изолированный класс, и парсер ничего не знает о нем. Этот класс используется для обработки hrd файлов. Формат hrd связывает синтаксические регионы с конкретной цветовой информацией, предназначенной для отображения - большей частью это непосредственные цвета - но так же там присутствует информация о парных конструкциях, проверке синтаксиса и других возможностей.

Итак, один из clr* методов - clrAddRegion используется для заполнения массива списков регионов. Он вызывается парсером в процессе работы. Конечно, вы можете предоставить свои собственные методы по обработке регионов и забыть о встроенных - но это довольно сложно, так как вам придется создавать дополнительно методы по разбору созданных регионов - а они имеют довольно сложную рекурсивную структуру.

соглашения о регионах

Регионы бывают трех типов: 1, 0, -1.

большей частью встречаются регионы с типом type == 0. Регион с типом 1 означают, что этот регион - начало блока - то есть весь текст до региона с типом -1 должен унаследовать свойства этого региона. Выглядит просто - но все усложняется с учетом того, что регионы могут быть вложены - из-за этого необходимы рекурсивные методы по разбору таких регионов (clrAssignRegions делает это).

Так же это значит что в общем случае регионы не есть прямое соответствие реальным цветам.

подготовка и разбор

Для начала парсинга вы должны создать массив регионов - SLineHL. 

  // totallines - необходимое количество линий.
  // в большинстве случаев - это число видимых на экране линий
  PLineHL lines = clrCreateRegions(totallines);
  // устанавливает начальную строку для разбора
  clrSetFirstLine(lines, 0);

После этого все готово для разбора. Вообще существует два метода разбора: QuickParse и FullParse. Первый должен использоваться для одновременного разбора всего текста - в иных случаях он может давать ошибки в выборе начальной схемы. Это происходит, если вы начинаете разбор со строки, которая принадлежит не схеме верхнего уровня - а вложенной. FullParse использует кэширование, которое гарантирует, что разобранный текст будет корректен. Это решает известную проблему многострочных блоков, когда не известно их начало.

После вызова одного из этих методов ваш массив lines содержит всю информацию о синтаксических регионах этой части текста. Для того, чтобы отобразить регионы, вы должны вызвать метод clrAssignRegions. Он создаст корректную структуру для отображения, и свяжет ее с цветами посредством класса CAssign. 

  // анализ всего текста
  cc->QuickParse(0, totallines);
  // dText - цвет текста по умолчанию
  PAssignData adback = adata->getcdata(cd->getregion("dText"));
  // подготавливает регионы к отображению
  clrAssignRegions(lines, adata, adback);

Помимо этого вы можете сжать структуры регионов. Эта операция необходима для неконсольного цветового вывода. Связано это с тем, что колорер создает неупорядоченные регионы - это значит они могут перекрываться и накладываться. Вызов метода clrCompactRegions гарантирует, что все регионы будут упорядочены в порядке возрастания и не будут перекрываться.

чистка

не забудьте удалить всю информацию после окончания работы. 

  clrDestroyRegions(lines);
  delete adata;
  delete cc;
  delete cd;

заметки по инсталляции

В общем-то, я хотел бы, чтобы при распространении и написании вашей программы вы придерживались этих рекомендаций. Ну, никто не настаивает естесственно.

В процессе распространения и установки вашей программы вы должны предполагать, что у пользователя уже установлен колорер - и считывать пути к нему из реестра, или же позволить пользователю вручную ввести их в настройках. Конечно, вы можете включать дистрибутив колорера в ваши программы - но никогда не интегрируйте HRC базу только с вашим приложением. Другими словами, если пользователь установит несколько программ, использующих библиотеку колорер, вы должны позволить всем программам работать с одной HRC-базой. Вы можете предложить пользователю установить колорер во время инсталляции и автоматически прописать в реестре все необходимые пути к колореру. Так же рекомендуется устанавливать колорер в какой-нибуть разделяемый каталог, к примеру c:\program files\colorer.

Если вы хотите использовать какие-то дополнения к колореру (к примеру свои собственные HRD настройки), вы должны инсталлировать их отдельно от библиотеки - как часть вашего приложения. Так же лучше проверять версию загружаемой hrc-базы методом CColorData.getversion() - и выдавать предупреждение при несовпадении версий.

Пара заметок об использовании цветовых схем hrd. Каждый hrd файл может определять не только цветовые атрибуты текста, но и различные атрибуты оформления редактора и его окон (смотрите regions.hrc). Заметьте, что метод CColorData->getregion("rname") позволяет вам узнать значение региона, связанное с именем "rname".

Помимо этого hrd формат не ограничивает интерпретацию значений цветов. Вы можете использовать шестнадцать консольных цветов, rgb тройку, или же устанавливать дополнительные атрибуты - такие как bold, italic. В случае нехватки четырех байтов, вы можете использовать символьные строки параметров (stext, sback) и реализовать собственный формат хранения отображений регионов.

расширенные возможности библиотеки

Основное назначение колорера - расцветка синтаксиса исходных кодов программ и предоставление пользователю возможности редактирования их в реальном времени. Но, дополнительно к этому, колорер содержит множество небольших возможностей и удобств, которые позволят вам, как разработчику сделать вашу программу более мощной (в смысле возможностей по написанию и отладке программ).

  • во первых, вы можете использовать библиотеку регулярных выражений колорера в вашей программе для реализации возможностей поиска/замены с их использованием.. (вторая после расцветки необходимая вещь для программиста).
  • Заметьте, что каждый тип в файле colorer.hrc имеет собственное поле description и поле name. Вы можете использовать поле name как уникальный идентификатор для хранения дополнительно информации редактора по этому языку (к примеру макросы, команды компиляции...)
  • В каждой структуре SLineHL, задающей регион содержится ссылка на схему, которой этот регион принадлежит. Для чего это может пригодиться? Это просто. Вы можете использовать getschemename для получения имени схемы. Далее, заметьте, что все схемы, вызываемые из блоков type имеют такое же имя, как имя их типа. Это значит что вы можете всегда узнать имя схемы в текущем положении курсора - а если существует тип с таким же именем, то сопоставить текущему положению свойства не глобального типа файла, а текущего вложенного. (к примеру jscript макросы в html файле).
  • Другая интересная возможность - поиск функций ошибок. Заметьте, что структура SAssignData содержит поле type. Описание этих типов вы можете найти в файле hrd.html. Вы заметили значения, означающие выражения функции или ошибки? Вы можете легко использовать их в вашей программе - разберите весь текст, и ищите регионы с соответствующим типом. Вы можете сделать списки синтаксических ошибок, или переходить на определение функции под курсором - все что пожелаете...
  • Другая интересная возможность параметра типа - орфографическая проверка текста. Согласитесь, что глупо проверять орфографию в C-коде - но это было бы оригинально в его комментариях. С этим же параметром type вы можете узнать, требует ли регион синтаксической проверки.
  • Ну и последняя возможность типа региона - это скрытые регионы. Такие регионы (с типом > 0xFF) не должны быть видимы при обычной работе (вы должны пропускать их). Сейчас только два значения этого типа существует - dpOpenStruct и dpCloseSrtuct. С ними вы можете очень просто сделать поддержку подсветки парных конструкций и их нахождения/выделения. Заметьте, что теперь одинаково просто выделять как обычные C/C++ скобки, так и сложные структуры XML кодов!
  • Ну, и под конец пара диких идей.
    • Полу-визуальный html редактор. Показывает все тэги - но с применением оформления их содержимого. (by me/cail)
    • Делать подсветку всего c/c++ блока - и с каждым уровнем вложенности все больше затемнять в нем цвет фона...(by dmitry kurmyshov/duil)
    • Делать не просто списки функций - а брать слово из-под курсора и искать функцию с таким именем (by vim на самом деле:))
