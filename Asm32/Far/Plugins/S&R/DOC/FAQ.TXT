[0] Нашел страшный и ужасный баг!!!

    Все может быть :-) Чтобы баг был  обнаружен  и  исправлен  присылайте  мне
следующую информацию:
 - описание бага и последовательность его получения
 - версия S&R/FAR/Windows
 - Содержимое реестра по адресу:
   HKCU\Software\Far\Plugins\S_And_R
   (или HKCU\Software\Far\Users\ИмяПользователя\Plugins\S_And_R, если вы
   запускаете FAR так: far.exe /u ИмяПользователя)
 - размер файла, на котором обнаружил себя баг
 - процессор/размер винта, на котором находится данный файл/свободное место
   на нем же/размер RAM
 - последнее сообщение от S&R/FAR/Windows
 - прочая информация, которую считаете полезной

 НЕ ПРИСЫЛАЙТЕ:
 - скриншоты (кроме тех,  что получены по ALT+INS), большие аттачи и т.п.

[1] А что это собственно такое?

    Вирус.   Гипнотизирует   людей,   заставляет   их   копировать   себя    с
увеличивающейся скоростью, при этом меняет в ваших  файлах  (конечно  же,  без
спроса!) некоторые жизненно важные байты :-)))

    А если серьезно, то краткий ответ на этот  вопрос  есть  в  readme.txt,  а
полного ответа даже я сам не знаю -  настолько  обширная  сфера  применения  у
данной программы.

[2] А как же поиск и замена с регулярными выражениями?

    Появилось в версии 0.3
    Просто включите соответствующую опцию.

[3] А если я хочу заменить 5 разных слов?

    На текущий  момент  есть  только  один  способ  сделать  такое  -  запусти
программу 5 раз (самый удобный способ - запуск из меню пользователя с  разными
файлами настроек). В будущем, возможно,  такую  "множественную"  замену  можно
будет сделать за один раз...

[4] А если я хочу заменить 1000 разных слов?

    Слушай, а не поможет ли тебе в данной ситуации PROMT? :-)

[5] Я хочу искать, используя все доступные кодировки.

    Поиск в панелях с использованием всех доступных кодировок появился плагине,
начиная с версии 1.8.

[6] Есть куча файлов, в которых на концах строк лишние пробелы. Trucer
    вызывать на каждом файле - замучаешься. Что делать?

    Есть два способа, правда, они не сработают  для  последней  строки  файла,
если она не оканчивается на знаки конца строки (и это правильно).

    [x] Регулярные выражения
Вариант 1 (для файлов, где строки оканчиваются на \r\n):
       Искать=\x20+\r\n   (или "\x20+$", см. настройки)
       [x] Заменить на=$$

Вариант 2 (универсальный): Искать=\x20+(\r?\n)
                           [x] Заменить на=$1

     Оба варианта предназначены для использования в панелях. В редакторе можно
использовать следующее:
     [x] Регулярные выражения
     Искать=\s+$
     Заменить на=(пустая строка)
     При этом можно отключить опцию "[ ]  Удалять  пустую  строку",  если  нет
желания, чтобы плагин удалил строки, состоящие только из пробелов.

[7] Есть куча файлов, хочется заменить множество пустых строк на одну, как?

    В панелях:
    Искать=(\r\n){2,}
    [x] Заменить на=$$$$
    [x] Регулярные выражения

[8] ... а если вообще хочу убрать все пустые строки?

    Тогда:
    [x] Заменить на=$$

[12] Хочу удалить строку, содержащую слово blablabla. Как?

    [x] Заменить на=$$
    [x] Регулярные выражения
IR> Искать=\r\n[^\n]*blablabla[^\n]*\r\n
Возможно, что лучше использовать такое:
    Искать=^[^\n]*blablabla[^\n]*\r\n

Примечание:
    С версии 1.0 этот регэксп верен при: [x] Весь файл как одна строка
    Если эта опция отключена, то можно использовать регэксп типа:
    Искать=\r\n.*blablabla.*\r\n

    В редакторе можно использовать:
    [x] Регулярные выражения
    [x] Удалять пустую строку
    Искать=^.*blablabla.*$
    Заменить на=(пустая строка)

"\r?\n". См. также FAQ#6

[20] А что за маразм получается? При поиске по маске *.* плодятся bak-файлы...

[21] Я хочу такое же меню для открытия файла во вьюере как по shift+f4. Как?

    S&R, начиная с версии 0.9, вам в этом не помощник. Используйте плагин  Far

[22] А зачем перегружать плагин всякими s&r:view и т.п.?

    Уже нет такого. Я выкинул это в версии 0.9.

[23] Я хочу поиск слов...

    Если поиск с регэкспами, то см. в хелпе про спецсимвол \b.
    Если обычный поиск, то "[x] Только целые слова".

[24] Я хочу, чтобы плагин автоматически запускался, когда я нажимаю enter на
     его конфигурационном файле.

    Для  этого  вам  следует  создавать  файлы  конфигурации  с   каким-нибудь
оригинальным расширением, например, ".sr". Тогда можно будет сделать следующую
ассоциацию на файлы "*.sr" по Enter'у: "s&r:i/!\!.!". После этого для  запуска
плагина можно будет просто нажимать Enter на файлах "*.sr"...

[25] Какая-то тормозная у тебя обработка регэкспов :(

    Обработкой  регэкспов  занимается  парсер  от  Константина  Ступника.   По
вопросам, касающимся скорости работы парсера, обращайтесь к нему...

[26] А это правда, что можно этим плагином строки нумеровать?

    Правда. Для этого можно использовать регэксп "\#" в строке замены...

[27] Как мне "очистить" вертикальный блок в редакторе?

    Искать=.
    Заменить на=\x20
    [x] Регулярные выражения
    () Выделенный текст

[28] Почему s&r не позволяет "склеивать" строки в редакторе?

    Потому что это не позволяет сделать неким стандартным  способом  сам  Фар.
Можно, конечно, взвалить на себя решение  этой  проблемы,  но  тогда  скорость
работы  плагина  в  редакторе  _существенно_  уменьшится.   Если   вы   хотите
плодотворно работать со знаками  конца  строки  (в  том  числе  и  "склеивать"
строки), то запускайте s&r в панелях и обрабатывайте нужный файл.

[29] Твои макросы ctrl-up/down глючат с mousewheel.

    Намакросьте эти действия на любые другие клавиши :)

[30] Хочу, чтобы найденные файлы помещались на временную панель.

    Появилось, начиная  с  версии  1.6,  включается  в  "настройки/поиск",  но
работает только с FAR 1.70 и выше.

[31] А как мне в этой программе указать область поиска "Искать только в
     текущей папке" и все остальное (аналогично alt-f7)?

    a) "Искать на всех дисках, кроме сменных"
       () Искать в каталогах: *
       [x] Обрабатывать подкаталоги

    b) "Искать по всему диску"
    Нет буквального аналога, вам придется или явно указать путь, или перейти в
корень диска и оттуда начать поиск.

    c) "Искать, начиная с текущей папки"
       () Искать по маске
       [x] Обрабатывать подкаталоги

    d) "Искать только в текущей папке"
       () Искать по маске
       [ ] Обрабатывать подкаталоги

    e) "Искать в отмеченных папках"
       () Искать в отмеченном

[32] Как мне удалить дублирующиеся строки из файла?

    Например, так...
    В панелях установите курсор на нужный файл, запустите s&r.
    () Искать в отмеченном
    Искать=^(.+\r\n)\1+
    Заменить на=$1
    [x] Регулярные выражения
    [ ] Весь файл как одна строка

[33] Как мне в каждой строке редактора поменять местами все, что расположено
     до знака '=' и после него?

    Искать=^(.*?)=(.*?)$
    Заменить на=$2=$1
    [x] Регулярные выражения

[34] Пункт плагина добавляется в меню плагинов программы просмотра только
     первого запуска S&R в панелях или в редакторе :(

    Очистите ваш кэш плагинов (можно использовать ClearPluginsCache.bat).

[35] Как написать регэксп, который в переводе на обычный язык означал бы
     "текст1 -- любая последовательность знаков, кроме пустой строки --
     текст2"?

    [x] Регулярные выражения
    [x] Весь файл как одна строка
    Искать=текст1((?!\r\n\r\n).)+?текст2
    Под \r\n\r\n подразумевается пустая строка - два подряд перевода строки  в
досовом формате. Если файл в формате UNIX, то используйте:
    Искать=текст1((?!\n\n).)+?текст2
    Универсальный вариант:
    Искать=текст1((?!\r?\n\r?\n).)+?текст2

[36] VerInfo: Как просмотреть  информацию  о  версии  файла,  находящегося  в
     архиве?

     Для этого нужно открыть файл  в  программе  просмотра  (F3)  и  запускать
VerInfo уже там.

[37] Замена "^$" на ""  не  удаляет  пустых  строк  в  редакторе,  даже  если
     включена опция "Удалять пустую строку".

     Плагин не умеет заменять что-то, если размер  найденного  равен  нулю.  В
панелях он вообще прекращает в этом случае работу, а в  редакторе  -  нет,  но
ничего и не заменяет, тем не менее. Если вы хотите удалить пустые  строки,  то
воспользуйтесь командой "F11/S&R/Удалить  лишние  строки",  введя  в  качестве
строки поиска регэксп "." (т.е. дословно получается, что дана команда  удалить
все строки, которые не содержат ни одного знака... что вам и нужно).

[38] Правда ли что S&R  может  заменить  "Временную  панель"  из  стандартной
     поставки FAR?

     Да, это возможно, начиная с  версии  2.0.  Если  вы  удалите  стандартный
плагин TmpPanel.dll, то список найденного внутренним  поиском  в  панелях  FAR
(Alt-F7) будет помещаться на "временную  панель"  от  S&R  (при  условии,  что
установлен temppanel.srs - системный плагин для S&R,  версия  FAR  больше  или
равна 1.70, включена опция "Обрабатывать команду OPEN_FINDLIST"  в  настройках
временной панели S&R).
     Учтите только, что эту замену стандартного плагина следует делать  только
тем, кого возможности temppanel.srs устраивают, ибо я вряд ли  буду  полностью
повторять все навороты последних  версий  "временной  панели"  FAR  (работа  с
командной строкой, "Безопасный режим панели" и прочее).

[39] Как мне сделать, чтобы настройки плагина в реестре всегда были одни и те
     же при старте FAR?

     Непосредственно  средствами  плагина  такое  не  сделать.   Экспортируйте
необходимые настройки в файл s_and_r_settings.reg и импортируйте его в  реестр
при каждом старте FAR командой "regedit -s s_and_r_settings.reg" - делать  это
можно макросом, у которого установлен флаг "Выполнять после запуска FAR".

[40] Для чего нужны в регэкспах для поиска операторы просмотра вперед/назад?

AY> Операторы просмотра вперёд/назад нужны  для  поиска  текста,  находящегося
AY> перед/после какого-нибудь другого текста, который мы не хотим захватить  в
AY> найденном вхождение строки поиска (удобно для замены).
AY> Примеры:
AY> 1. Искать=(?<=AA)YYY
AY>    Заменить на=X
AY>    Заменяет текст "YYY" на "X", если перед ним есть текст "AA".
AY> 2. Искать=AA(?=YYY)
AY>    Заменить на=X
AY>    Заменяет текст "AA" на "X", если после него есть текст "YYY".

[41] Почему при использовании регулярных  выражений  выдается  сообщение  "Не
     задана строка поиска!",  когда  в  строке  поиска  содержится  выражение,
     начинающееся со знака '/'?

     Это сообщение выдается только тогда, когда строка поиска  на  самом  деле
пуста. В случае с регэкспом замены типа  "/bla/"  сообщение  о  пустой  строке
выдается только, когда  включена  опция  "Настройки/Поиск/Работа  без  //  при
поиске с регэкспами", потому что в этом случае плагин сам добавляет эти  слеши
- получается регэксп типа "//bla//", который считается пустым, т.к.  регэкспом
считается то, что расположено между первыми двумя слешами.

[42] К чему такие сложности дистрибутива в виде вложенных архивов?

     Это простейшее сито, позволяющее отделить лузеров от юзеров :-)

+[43] В программе просмотра (но не в  редакторе)  ищем  регэксп  \bx. Операция
     продложения поиска считает, что  условие  \b  всегда  истинно  и  находит
     второй "x" в "xx". Разве это правильно?

     По своей сути, нет, не очень  правильно.  В  случае  с  S&R  это  вызвано
спецификой работы  в  программе  просмотра:  файл  начинает  обрабатываться  с
текущей позиции, а  предыдущий  знак  не  учитывается,  поэтому  \b  в  начале
выражения  всегда  считается  истинным.   Стимула   запрограммировать   другое
поведение я пока не заметил.
